# 商品匹配实验候选流程

本文件是待验证的方法说明，不替换 V1.4 的 Skill 入口或经营经验。仅显式请求匹配研究时使用。匹配指数不是同款概率、采购成功率或删除规则。

1. 用 `scripts/matching_audit.py --config local.json --work work/matching_run` 只读检查四份 Excel。配置含 `amazon`、`action` 两个数组，每项是 `path` 与 `snapshot_date`。可记录 `source_alias_authorization`。按实际 ASIN 保存每条观察，不以 Parent ASIN 合并。来源文件日期仅为快照日期，不冒充抓取时间。最新缺价保持缺失。
2. 复用冻结的 10,037 条 Action 品名索引。历史价格和规格另存本地，并按 SKU、原名和日期绑定。名称不一致的历史规格不自动拼接。缺币种不猜欧元。
3. `scripts/matching_experiment.py prepare --work work/matching_run` 固定随机种子与 200 条样本，召回20条，保留原检索排名。所有输入和方法代码建立散列；不得因结果不理想重抽。
4. 分别运行 `run --method A` 与 `run --method B`。A仅品名，B增加规格、变体与类目。通过现有真实模型适配器在隔离上下文中检查20条并精排5条。两组不共享输出，均不接收价格或经营偏好。
5. 保留六种关系：同款、同类型、功能替代、同需求、不相关、信息不足。AI证据只是候选，不是人工事实标签。允许没有可确认匹配。
6. C是B后的可比价格实验。只有相近日期、明确币种、来源绑定、AI明确规格相同且两侧件数有原文依据时才计算候选单位价格比；独立事实审核仍待完成。不满足条件的C为空，不能把B回退称为C成功。
7. 输出独立事实审核与经营研究审核两组空白字段。缺人工标签时 Precision@1、Recall@20 和正式准确率都留空。

完成A/B后用 `collect --work work/matching_run` 生成ABC前5候选、比较统计和60对审核候选。同一方法禁止并发执行；A与B可独立并行。失败可在原目录重跑，复用已通过的来源绑定缓存。遗留锁必须先核实原进程已经结束再移除，不可自动抢锁。模型原始响应和错误记录不删除。

## 暂定指数与敏感性试验

名称维度复用现有检索分数，截断到0–100（它包含词、字符、SVD和标题主词线索，不是纯编辑距离）。类型维度为显式候选关系的实验量表：同款100、同类型80、功能替代50、同需求20、不相关0、信息不足不可计算。规格相同100、不同0、未知空；类目支持100、明确冲突0、未知空。

同时展示三组未校准权重（名称、主体类型、规格、类目）：60/30/8/2、35/45/15/5、20/60/15/5。仅对可用维度归一，同时输出证据权重覆盖。A的规格和类目始终空。指数上限分别为100/89/64/34/14；信息不足不给综合数值。不同规格不等于无关，不能仅靠低规格分改变商品关系。

这些数字是研究假设，不是经过独立样本证明的最佳权重或阈值。报告以中间权重呈现，同时给出排序敏感性；不存在校准获胜方案。独立审核完成后才可决定权重。

价格任务分开：单位价格可比性是门槛；价格带接近程度是 `100 * min(ratio, 1/ratio)`，其中ratio为两侧可比单位价之比。只有C覆盖的配对才试算 `(1-w)*B + w*价格带接近度`，w取5%、10%、20%。价格不改写商品关系或身份，C仍遵守关系上限。不以接近Action零售价证明匹配更正确。历史报价不是实时询价，也未统一促销、渠道或税务条件。

## 审核与隐私

样本及完整召回列表保存在本地 `work/`，无需重新创建数据库或分类器。模型调用、token、耗时、失败、散列均保留。回放仅复用同输入同提示缓存，不伪造模型调用。原表、冻结Action库、V1.4与密封集不改动。

公开仓库只保存通用代码、合成测试和匿名统计。原始报价、商品行、内部经营反馈和审核表只留本地。审核者应从原始商品页面和规格材料判定事实关系，Recall@20还需在完整Action参照库中检索遗漏参照，不能只审前20条就宣称召回率。Owner另行确认研究价值；两种结论不混用。
