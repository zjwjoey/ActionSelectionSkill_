## What changed

Each actual AI analysis binds source/input/prompt/model/method and supplies:

- literal sold-subject span and specific type;
- sold form: ordinary good, bundle, universal accessory, host component,
  installed component, whole machine, whole system or unknown;
- dependency and separate candidate operating boundary;
- reference role, literal source/reference spans, bounded relationship,
  limitations and coverage of subject versus partial bundle/host/category;
- distinct literal functional features when an automation boundary is proposed.

Use `rules/boundary-v0.2/evidence_prompt.md`. A Python validator checks evidence
shape and bindings; actual language reasoning is still required. A valid schema
does not prove the AI's interpretation correct. No placeholder or human labels.

Installed parts do not establish complete industrial machines. Special-purpose
gun-storage boundaries have no confirmed policy in this run and stay review.
The complex-automation candidate requires at least three distinct named
functions; dust base and dust disposal count once. Three containers without a
stated function do not prove automatic water management. This threshold is an
experimental heuristic, not a human-validated assortment standard. Distinct
tags cannot reuse overlapping literal spans. An unknown or absent Action
reference never excludes. Partial coverage of one bundle component is not proof
of the entire bundle.
